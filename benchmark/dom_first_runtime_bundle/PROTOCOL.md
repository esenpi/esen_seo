# DOM-first Application Runtime Bundle Benchmark Protocol

This protocol was frozen before the first bundle fixture build and measurement.
Thresholds must not be fitted to observed results.

## Pinned toolchains

- Dart SDK 3.6.2
- Flutter 3.27.4
- Node.js 23.4.0
- Next.js 16.2.11 with React 19.2.0
- Playwright 1.62.0
- Exact Chromium version recorded with the result

## Candidate

The candidate is one route-scoped, application-authored JavaScript artifact
containing exactly three independently state-owning adapters:

1. Tabs with an application transition;
2. Collection search, category, sort, pagination and URL restoration with an
   application transition;
3. Stepper state plus the closed active-panel focus effect with an application
   transition and a build-time interaction-id admission list.

The bundle compiler canonicalizes member order. The manifest binds the complete
member set to the bundle identity, source bytes, compiler version and size.
The route loads one verified script tag. Existing single-runtime artifacts and
their generated bytes are outside this candidate and must remain unchanged.

## Cells

Every cell carries equivalent content, CSS and the complete interaction
sequence:

1. hand-written DOM as the practical floor;
2. statically rendered Next.js as the competitive reference;
3. esen_seo DOM-first with one compiled application runtime bundle;
4. the existing visible shell followed by a Flutter release build.

The first three cells contain every tab panel, collection item and step body in
the initial HTML. The DOM-first network log must contain no Flutter artifact
and its document must contain exactly one application-runtime script tag.

## Scripted sequence

Every run starts at `/?campaign=bench#content` and performs the same sequence:

1. select the second tab and verify its panel;
2. search the collection for `dart` and verify the filtered result;
3. clear search, select the `Guides` category, select title order and advance
   to page two;
4. restore page one with Back and page two with Forward while preserving the
   unrelated query parameter and fragment;
5. advance the Stepper and verify that the second panel is selected and focused;
6. select the first tab again and verify that Collection and Stepper state did
   not change.

The Flutter cell performs the equivalent state changes without browser URL
restoration because native Flutter collection state deliberately does not own
browser History. Its transfer, LCP, TBT, interaction and CLS measurements remain
part of the comparison; URL assertions apply only to permanent DOM cells.

## Profile

- Cold HTTP cache and a fresh browser context for every run
- Mobile viewport 390 x 844, device scale factor 2
- 1.6 Mbit/s down, 750 Kbit/s up and 150 ms round-trip latency
- 4x CPU slowdown through the Chrome DevTools Protocol
- Seven runs per cell
- Median decides acceptance; p75 is recorded
- Fixed rotating order: ABCD, BCDA, CDAB, DABC, ABCD, BCDA, CDAB

Field INP has a post-release p75 target of 200 ms and is not part of this lab
matrix. CLS has no relative bound.

## Relative gate

For every other metric where Next.js beats the Flutter baseline, DOM-first
must be numerically closer to Next.js than to Flutter. If Flutter already
matches or beats Next.js, the absolute ceiling alone decides. Both applicable
parts must pass for the compiled candidate to remain.

## Functional and security gates

- A bundle contains between two and four entries and at most one entry per
  adapter family. `stepper` and `stepper-effects` are one ownership family and
  cannot coexist.
- Bundle identity, member kinds and member order are deterministic. Reordering
  the same request produces identical compiler input and output bytes.
- Every library passes the existing complete pure-Dart import-graph and
  no-held-state checks before compilation.
- Unknown kinds, duplicate families, invalid symbols, invalid runtime ids,
  invalid Stepper admission ids, stale manifests and mismatched member sets
  fail before delivery.
- A route cannot combine a bundle member with the corresponding package-owned
  runtime. Existing single-runtime route and artifact APIs remain compatible.
- One invalid bundle member rejects the complete build or load. No partial
  bundle is delivered and no adapter mutates the document before its own
  complete component validation succeeds.
- One component's accepted actions cannot alter another component's state.
- The generated JavaScript remains CSP-compatible and passes the existing raw
  script-tokenizer and string-to-code checks.
