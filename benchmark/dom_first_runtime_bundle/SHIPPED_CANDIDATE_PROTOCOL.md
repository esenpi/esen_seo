# Shipped Runtime Bundle Benchmark Protocol

This follow-up protocol was frozen before the first browser measurement of the
supported bundle candidate. It does not replace or amend the original failed
Collection candidate in `PROTOCOL.md`.

## Pinned toolchains

- Dart SDK 3.6.2
- Flutter 3.27.4
- Node.js 23.4.0
- Next.js 16.2.11 with React 19.2.0
- Playwright 1.62.0
- Exact Chromium version recorded with the result

## Candidate

The candidate is one route-scoped, application-authored JavaScript artifact
containing exactly three independently state-owning adapters:

1. Tabs with an application transition;
2. Carousel with an application transition;
3. Stepper state plus the closed active-panel focus effect with an application
   transition and a build-time interaction-id admission list.

The bundle compiler canonicalizes member order. The manifest binds the complete
member set to the bundle identity, source bytes, compiler version and size. The
route loads one verified script tag. Existing single-runtime artifacts and
their generated bytes are outside this candidate and must remain unchanged.

## Cells

Every cell carries equivalent content, CSS and the complete interaction
sequence:

1. hand-written DOM as the practical floor;
2. statically rendered Next.js as the competitive reference;
3. esen_seo DOM-first with one compiled application runtime bundle;
4. the existing visible shell followed by a Flutter release build.

The first three cells contain every tab panel, carousel slide and step body in
the initial HTML. The DOM-first network log must contain no Flutter artifact
and its document must contain exactly one application-runtime script tag.

## Scripted sequence

Every run performs this fixed sequence:

1. select the second tab and verify its panel;
2. advance the Carousel and verify its second slide;
3. move the Carousel to its final slide through the keyboard and verify it;
4. advance the Stepper and verify that the second panel is selected and focused;
5. select the first tab again;
6. verify that the Carousel remains on its final slide and the Stepper remains
   on its second panel.

The Flutter cell performs the same application state changes through the same
three pure transitions. The DOM cells additionally exercise keyboard event
wiring and the Stepper focus effect through the browser apply boundary.

## Profile

- Cold HTTP cache and a fresh browser context for every run
- Mobile viewport 390 x 844, device scale factor 2
- 1.6 Mbit/s down, 750 Kbit/s up and 150 ms round-trip latency
- 4x CPU slowdown through the Chrome DevTools Protocol
- Seven runs per cell
- Median decides acceptance; p75 is recorded
- Fixed rotating order: ABCD, BCDA, CDAB, DABC, ABCD, BCDA, CDAB

## Relative gate

For every other metric where Next.js beats the Flutter baseline, DOM-first
must be numerically closer to Next.js than to Flutter. If Flutter already
matches or beats Next.js, the absolute ceiling alone decides. Both applicable
parts must pass for the compiled candidate to remain.

## Functional and security gates

- The generated runtime remains below the unchanged raw and gzip limits.
- Bundle identity, member kinds and member order are deterministic. Reordering
  the same request produces identical compiler input and output bytes.
- Every library passes the existing complete pure-Dart import-graph and
  no-held-state checks before compilation.
- The delivered manifest lists exactly Tabs, Carousel and Stepper Effects.
- The DOM-first source contains all nine content bodies before JavaScript runs.
- The DOM-first route requests no Flutter bootstrap, application, CanvasKit or
  SkWasm artifact.
- Exactly one inline application-runtime script is present; no second runtime
  script is present or requested.
- One component's accepted actions cannot alter another component's state.
- Every scripted action must reach its expected state before two subsequent
  animation frames complete.
- The generated JavaScript remains CSP-compatible and passes the existing raw
  script-tokenizer and string-to-code checks.
